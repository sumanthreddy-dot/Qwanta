GreenQ-Fleet — Model Prediction & Visualization Specification
Project-ready document describing how the generated multi-model fuel-consumption predictions are incorporated into GreenQ-Fleet and displayed as graphs for the fleet optimizer.
1. Purpose
The prediction layer provides fuel-consumption estimates for operating conditions before the optimizer selects the final fleet configuration. These predictions feed fuel-used, fuel-cost and Well-to-Wake (WTW) GHG calculations, which then become objectives for the quantum-inspired multi-objective optimizer.

3. Scenario prediction grid
The generated scenario file contains the combinations used for the prototype: weather scenarios, operating speeds, fuel options and shore-power decisions. The ML prediction itself is based on operational/environmental features; fuel type and shore power are handled downstream in the cost/GHG layer unless a future fuel-specific model is trained.

4. Graphs to incorporate into the Streamlit project
Fuel consumption vs speed
Line chart. X-axis: speed (kn). Y-axis: predicted fuel consumption (L/hr). Plot XGBoost, LightGBM and CatBoost; allow the user to select other models.
Weather impact
Line chart. X-axis: speed (kn). Y-axis: predicted fuel (L/hr). Use separate selectable weather scenarios: Normal, Bad Weather and Severe Weather.
Model comparison
Bar chart at a selected operating condition showing predicted L/hr for all nine models.
Optimization impact
After QIGA/NSGA-II produces solutions, compare total fuel, cost and WTW GHG of the selected solution against Pareto alternatives.
5. Data flow inside GreenQ-Fleet
HISTORICAL / SCENARIO DATA
        ↓
MODEL PREDICTION (XGBoost / CatBoost / LightGBM)
        ↓
Predicted fuel consumption (L/hr)
        ↓
Voyage duration → total fuel used
        ↓
Fuel price + WTW emission factor
        ↓
Fuel cost + WTW GHG
        ↓
QIGA / QIEA multi-objective optimization
        ↓
Pareto solutions → Streamlit graphs → final recommendation
6. Important modeling note
The original research dataset contains a single Kamsarmax operational dataset. The fleet fields and scenario fields added for GreenQ-Fleet are prototype/synthetic inputs and must be clearly labeled as such. Do not present them as measurements from the published dataset.
The current CatBoost optimizer-compatible model should not use future engine variables such as shaft RPM, shaft power or shaft torque as decision-time inputs. Those variables are useful for an analysis model but are unavailable when the optimizer is choosing speed/fuel/fleet decisions.

10. Implementation rule
The Streamlit dashboard should let the user choose weather scenario, speed, model and (where relevant) fuel/shore-power assumptions. The graph should update from the stored prediction/scenario CSV rather than retraining a model on every interaction. The optimizer can call the integrated predictor for candidate fitness.
